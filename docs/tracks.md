# Tracks

A track is a folder with a PNG and a YAML; the simulator loads the generated `track.json`
at launch, so adding a track never needs a Unity rebuild.

```
tracks/<name>/
    design.yaml    optional: waypoints + width, rendered to map.png by track_design.py
    map.png        white = drivable corridor, everything else = not drivable
    track.yaml     name, resolution, direction, checkpoints, walls, cones
    track.json     GENERATED by track_build.py: walls, centreline, checkpoints, spawn, cones
    preview.png    GENERATED picture (also shown on the leaderboard site)
```

## Designing a new track

```bash
mkdir tracks/hairpins
cat > tracks/hairpins/design.yaml <<EOF
width: 2.0
points: [[0, 0], [12, 0], [12, 4], [4, 4], [4, 8], [14, 8], [14, 12], [0, 12]]
EOF
cat > tracks/hairpins/track.yaml <<EOF
name: Hairpins
direction: ccw
checkpoints: 20
walls: {diameter: 0.33}
EOF
tools/track_design.py tracks/hairpins/design.yaml     # map.png + resolution/origin into track.yaml
tools/track_build.py tracks/hairpins                  # track.json + preview.png
./feb-sim run --track hairpins
```

The corridor is a smooth closed spline through the waypoints (any number, any shape, no
self-intersections). Any other PNG works too: hand-painted in GIMP, or a SLAM occupancy grid
of a real track (`tracks/porto` is the RoboRacer Porto map, resolution and origin from its
ROS `map.yaml`). Grey "unknown" pixels count as not drivable.

## track.yaml

| Key | Meaning |
|---|---|
| `name` | shown in the simulator and on the site |
| `resolution`, `origin` | metres per pixel and map position of the bottom-left pixel (written by track_design) |
| `direction` | `ccw` or `cw` driving direction |
| `checkpoints` | lap checkpoints; checkpoint 0 is the finish line |
| `start` | optional `[x, y]` finish-line position; default: the straightest section |
| `walls.diameter` | air-duct diameter (0.33 m like the league; omit the key for a cone-only track) |
| `cones.spacing` | metres between cones on each edge, blue left, yellow right (omit for none) |

## Practice versus secret tracks

Everything under `tracks/` ships inside the simulator app and is public. Keep competition
tracks in a private folder (e.g. `~/feb-secret-tracks/<name>`, same layout) and point the
event file at it; the harness passes the folder to the headless simulator directly. After
the event, move the folder into `tracks/` and commit: it becomes a practice track.
