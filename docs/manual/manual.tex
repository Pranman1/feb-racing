\section{What it is}

FEB Racing is a sim-racing programme for autonomous driving. Members write a ROS~2 driving
stack for a 1:10 scale RoboRacer car, run it in the FEB Simulator on their own laptop, and post
lap times to a public leaderboard. Twice a semester the organiser runs a competition on a
secret track, with the same rules as the RoboRacer Sim Racing League.

The simulator is a fork of the AutoDRIVE Simulator (Unity). The car, its sensors and its
physics are the league's RoboRacer model, unchanged, so a stack that works here works in the
league too.

\subsection{The pieces}

\begin{tabularx}{\linewidth}{p{3.3cm}Xp{3.4cm}}
\toprule
Piece & What it does & Who touches it\\
\midrule

Devkit container & Docker image \file{ghcr.io/pranman1/feb-devkit}: ROS~2 Humble plus the AutoDRIVE bridge that turns the WebSocket into ROS~2 topics. The member's code runs inside it. & Members' code runs inside it\\
\file{stack/} & The member's ROS~2 packages. Mounted into the container and built on every start. & Members\\
\file{tracks/} & Public tracks. PNG and YAML in, \file{track.json} out. Shipped inside the app. & Organiser adds, members use\\
\file{feb-sim} & The member launcher: setup, run, practice, submit, shell, stop. & Members\\
\file{feb-race} & The organiser harness: events, nightly reruns, verification, head-to-head brackets. & Organiser\\
\file{results/}, \file{events/}, \file{submissions.yaml} & The data behind the leaderboard site. & Harness writes, members' pull requests add\\
Site & GitHub Pages, rebuilt on every push to \file{main}. & Read-only\\
\bottomrule
\end{tabularx}

\subsection{Data flow while driving}

\begin{lstlisting}
lidar, imu, encoders, camera, lap/collision counts --> bridge --> /autodrive/roboracer_1/* --> your node
your node --> /autodrive/roboracer_1/steering_command, throttle_command --> bridge --> simulator
\end{lstlisting}

The car takes exactly two inputs and everything else is a sensor:

\begin{itemize}
  \item \texttt{steering\_command}, \texttt{std\_msgs/Float32} in $[-1, 1]$: full left to full right, $\pm 0.5236$~rad. The actuator lags about 0.25~s and slews at 3.2~rad/s.
  \item \texttt{throttle\_command}, \texttt{std\_msgs/Float32} in $[-1, 1]$. \textbf{Zero is a hard brake}, not coasting. A car that wants to keep moving must never send zero.
\end{itemize}

\subsection{Sensors (namespace \texttt{/autodrive/roboracer\_1/})}

\begin{tabularx}{\linewidth}{p{5.2cm}p{4.3cm}X}
\toprule
Topic & Type & Notes\\
\midrule
\texttt{lidar} & \texttt{sensor\_msgs/LaserScan} & 1080 beams over 270\textdegree, 0.06 to 10~m, 40~Hz\\
\texttt{imu} & \texttt{sensor\_msgs/Imu} & orientation, angular velocity, linear acceleration\\
\texttt{left\_encoder}, \texttt{right\_encoder} & \texttt{sensor\_msgs/JointState} & wheel angle in rad; wheel radius 0.059~m\\
\texttt{steering}, \texttt{throttle} & \texttt{std\_msgs/Float32} & actuator feedback\\
\texttt{front\_camera} & \texttt{sensor\_msgs/Image} & forward camera (cone tracks)\\
\texttt{ips}, \texttt{odom}, \texttt{tf} & pose & ground truth: \textbf{training and debugging only}\\
\texttt{lap\_count}, \texttt{lap\_time}, \texttt{last\_lap\_time}, \texttt{best\_lap\_time}, \texttt{collision\_count} & counters & scoring: \textbf{training and debugging only}\\
\texttt{reset\_command} & command & respawn: \textbf{training and debugging only}\\
\bottomrule
\end{tabularx}

\medskip
Wheelbase 0.324~m, half width 0.135~m, steady-state speed about 23~m/s per unit throttle.
With a window open the bridge exchanges data at about 10~Hz (each exchange reads the
cameras back from the GPU); headless it reaches 20 to 40~Hz. Scored runs go through a proxy
fixed at 10~Hz for everyone, so a driver must cope with 10~Hz. The starter kit does.

\section{Rules}

These follow the RoboRacer Sim Racing League.

\rulebox{
\begin{itemize}
  \item One attempt is 1 warm-up lap plus 10 timed laps. Total time is the sum of the timed laps plus \textbf{10~s per collision}.
  \item Not finishing within \textbf{300~s} is DNF, ranked after every finisher by laps completed. More than \textbf{10 collisions} is DSQ.
  \item Each team gets the number of attempts stated in the event; the best counts.
  \item \textbf{Restricted topics at race time}: \texttt{ips}, \texttt{odom}, \texttt{tf}, the lap and collision counters, and \texttt{reset\_command}. The harness records which nodes subscribe to them during the run and flags the result on the site. Use them freely while developing.
  \item Everything a submission needs starts from the container's entrypoint (\file{/home/autodrive\_devkit.sh}), never from \file{.bashrc}.
  \item Head-to-head: car-to-car contact counts as a collision for both cars and respawns them side by side. Finishing order is most laps first, then the finish time including penalties.
\end{itemize}}

\section{Install (once, about 15 minutes)}

\subsection{Prerequisites}

\begin{tabularx}{\linewidth}{lX}
\toprule
OS & Install\\
\midrule
macOS & Docker Desktop (\url{https://docker.com}), Python~3 (comes with Xcode command line tools: \cmd{xcode-select --install}), GitHub CLI (\cmd{brew install gh})\\
Windows & Docker Desktop with the WSL~2 backend, Python~3 from python.org, GitHub CLI (\cmd{winget install GitHub.cli}). Run the commands below in Git Bash or WSL.\\
Linux & \cmd{sudo apt install docker.io python3 gh}, then add yourself to the \texttt{docker} group and log in again\\
\bottomrule
\end{tabularx}

\medskip
Start Docker Desktop before anything else. Then log the GitHub CLI in once: \cmd{gh auth login}.

\subsection{Get the repo and the simulator}

\begin{lstlisting}
git clone https://github.com/Pranman1/feb-racing
cd feb-racing
./feb-sim setup --team "Your Team"
\end{lstlisting}

\cmd{setup} checks Docker, pulls the devkit image, and downloads the simulator app for your
OS into \file{\textasciitilde/.feb-sim/app/}. The team name is what your results are posted under;
use the name your team registers in \file{submissions.yaml}.

\subsection{First drive: manual}

\begin{lstlisting}
./feb-sim run
\end{lstlisting}

A window opens on the \emph{FEB Loop} track in Driver's Eye view. Nothing drives by itself:
with no stack given, the launcher starts no driver and no opponent. Arrow keys steer and
throttle. The menu in the top-left has the Manual/Autonomous button, the Track button (cycles
the built-in tracks), the Cars button (more cars on the grid) and the camera choices.

\medskip
\textbf{macOS, if the app does not open} (``damaged'' or ``cannot be opened''): the app is not
signed by Apple. Run once:
\begin{lstlisting}
xattr -dr com.apple.quarantine ~/.feb-sim/app/mac/"FEB Simulator.app"
codesign --force --deep -s - ~/.feb-sim/app/mac/"FEB Simulator.app"
\end{lstlisting}

\section{Write your driver}

\subsection{Where the code lives}

Copy the starter kit into your own folder. \file{stack/} is yours and is ignored by git in
this repo, so nothing you do there conflicts with updates.

\begin{lstlisting}
cp -r starter_kit/feb_driver stack/
\end{lstlisting}

\begin{lstlisting}
stack/feb_driver/
    feb_driver/reactive_driver.py    THE DRIVER. Subscribes to lidar + encoders, publishes steering + throttle
    config/driver.yaml               its tuning knobs (speeds, gap bubble, filters, throttle law)
    launch/drive.launch.py           starts the driver with the yaml
    feb_driver/sysid_probe.py        stage 2: drives test inputs and records a bag
    tools/sysid_fit.py               stage 2: fits the recorded bag
    package.xml, setup.py            standard ROS 2 Python package files
\end{lstlisting}

\file{reactive\_driver.py} is about 170 lines. Per lidar scan it cleans the scan, zeroes a safety
bubble around the nearest return, aims into the widest gap, picks a speed from the room ahead
and the steering angle, and turns that into a throttle as feed-forward plus a bounded trim.
Everything is commented. \file{driver.yaml} exposes every number.

You can add more packages next to \file{feb\_driver}, more nodes, C++ packages, anything
that builds with \cmd{colcon}. The container builds everything under \file{stack/} on start.

\subsection{Run it on the simulator}

\begin{lstlisting}
./feb-sim run --stack "ros2 launch feb_driver drive.launch.py"
\end{lstlisting}

What happens, in order: the launcher starts the devkit container with \file{stack/} mounted
inside it; the container builds your packages and starts the bridge; the simulator starts,
connects to the bridge, and is put in Autonomous mode; the container starts your launch
command. The car drives.

Edit, save, run the same command again. Each run is a fresh build (a few seconds for Python).

\subsection{Useful options}

\begin{tabularx}{\linewidth}{lX}
\toprule
Option & Effect\\
\midrule
\texttt{--track porto} & another built-in track (\texttt{loop}, \texttt{loop\_cones}, \texttt{porto}), or a path to any track folder\\
\texttt{--mode manual} & keep the keyboard even with a stack running\\
\texttt{--opponent normal} & the house racer in car two (\texttt{slow} 1.5, \texttt{normal} 2.0, \texttt{fast} 2.5~m/s, or \texttt{map}). Needs \texttt{--stack}. Not on Porto (single-car track).\\
\texttt{--cars 2} & a second, undriven car on the grid\\
\texttt{--noise 1} & lidar range noise and dropouts; \texttt{--noise "range\_sigma:=0.05 latency:=0.05"} sets them\\
\texttt{--lidar-hz 10} & slower lidar, as a real bridge often delivers\\
\texttt{--camera Trackcam} & start in another view (\texttt{"God's Eye"}, \texttt{Trackcam}, \texttt{"Driver's Eye"})\\
\bottomrule
\end{tabularx}

Car one is always \emph{your} car: the Manual/Autonomous button, the keyboard, the Driver's
Eye camera and topic namespace \texttt{roboracer\_1} all belong to it. Your container never sees
any other car.

\subsection{Debug}

\begin{lstlisting}
./feb-sim shell                 # a ROS 2 shell inside the running container
ros2 node list
ros2 topic hz /autodrive/roboracer_1/lidar
ros2 topic echo /autodrive/roboracer_1/throttle_command
rqt
./feb-sim stop                  # stop the container(s) and the simulator
\end{lstlisting}

The container log (build errors, your node's output) is \cmd{docker logs feb-devkit}.

\section{Score yourself and post it}

\begin{lstlisting}
./feb-sim practice --stack "ros2 launch feb_driver drive.launch.py" --track loop
./feb-sim submit
\end{lstlisting}

\cmd{practice} runs one attempt under competition rules: warm-up plus 10 timed laps, 10~s per
collision, DNF after 300~s, through the 10~Hz proxy. It prints the result and saves
\file{runs/<id>/} with \file{result.json}, logs and a ROS bag.

\cmd{submit} opens a pull request with the result file. A check validates it and merges it,
and you appear on that track's practice board as \emph{unverified}. The organiser's nightly
rerun of your image turns it \emph{verified}.

\section{Race the house racer}

\begin{lstlisting}
./feb-sim run --stack "ros2 launch feb_driver drive.launch.py" --opponent normal
\end{lstlisting}

The house racer starts in car two only when your stack starts your car. It is the smooth
lidar driver at a conservative pace with zero wall contact: the thing a new stack has to
overtake. It follows a car ahead rather than ramming it.

\section{Enter competitions}

Competitions run on the organiser's PC from a Docker image you publish. Build it from the
starter Dockerfile, which starts from the devkit image, copies \file{stack/} in, builds it and
sets the launch command:

\begin{lstlisting}
docker build -t <dockerhub-user>/feb-racer:v1 -f starter_kit/Dockerfile stack/
docker push <dockerhub-user>/feb-racer:v1
\end{lstlisting}

If your launch command differs from the starter's, change the \texttt{FEB\_LAUNCH} line in a
copy of the Dockerfile. Then register: add your team, GitHub logins and image to
\file{submissions.yaml} in a pull request:

\begin{lstlisting}
teams:
  - name: Your Team
    members: [github-login-1, github-login-2]
    image: docker.io/<dockerhub-user>/feb-racer:v1
\end{lstlisting}

Competitions and nightly reruns pull that image. Update the tag and the yaml whenever you
want a new version raced.

\section{Learning path}

\begin{enumerate}
  \item \textbf{Reactive driving.} Tune \file{driver.yaml}. Target: 10 clean laps on \texttt{loop} under 100~s.
  \item \textbf{System identification.} \cmd{ros2 launch feb\_driver sysid.launch.py} records throttle steps, a coast and a chirp; \cmd{python3 tools/sysid\_fit.py stack/sysid\_bag} inside the container fits the gain and lags.
  \item \textbf{Localisation and a map.} Build a map from lidar, localise on it. Check against \texttt{ips} while developing; never subscribe to it at race time.
  \item \textbf{Raceline and controller.} A minimum-curvature line with a speed profile, tracked by pure pursuit, then MAP or MPC. Lap times halve here.
  \item \textbf{Realism.} \texttt{--noise}, \texttt{--lidar-hz 10}, \texttt{--opponent}, the cone track.
\end{enumerate}

\section{If something goes wrong}

\begin{tabularx}{\linewidth}{lX}
\toprule
Symptom & Cause and fix\\
\midrule
Nothing drives & Correct without \texttt{--stack}. With a stack: the build failed or the node crashed, see \cmd{docker logs feb-devkit}; or the mode button says Manual.\\
Port 4567 in use & Another bridge container is running: \cmd{./feb-sim stop}.\\
Car surges and stops & Throttle reaching zero (a hard brake). Keep feed-forward plus a bounded trim; see the starter's throttle law.\\

\bottomrule
\end{tabularx}

\section{Tracks}

A track is a folder. The simulator reads \file{track.json} at launch, so adding a track never
needs a Unity rebuild; it needs an app release only to ship inside the app.

\begin{lstlisting}
tracks/<name>/
    design.yaml    optional: waypoints + width, rendered to map.png
    map.png        white = drivable corridor, everything else = not drivable
    track.yaml     name, resolution, direction, checkpoints, walls, cones, max_cars
    track.json     GENERATED: walls, centreline, checkpoints, spawn, cones
    preview.png    GENERATED: picture for the site
\end{lstlisting}

\subsection{Create a new track (two commands)}

\begin{lstlisting}
mkdir tracks/hairpins
cat > tracks/hairpins/design.yaml <<EOF
width: 2.0
points: [[0, 0], [12, 0], [12, 4], [4, 4], [4, 8], [14, 8], [14, 12], [0, 12]]
EOF
cat > tracks/hairpins/track.yaml <<EOF
name: Hairpins
direction: ccw
checkpoints: 20
walls: {diameter: 0.33}
EOF
tools/track_design.py tracks/hairpins/design.yaml   # map.png, resolution and origin into track.yaml
tools/track_build.py tracks/hairpins                # track.json + preview.png
./feb-sim run --track hairpins                      # look at it
\end{lstlisting}

The corridor is a smooth closed spline through the waypoints: any number, any shape, no
self-intersections. Any other PNG works too: hand-painted, or a SLAM occupancy grid of a real
track (Porto is one; its resolution and origin come from the ROS \file{map.yaml}).

\begin{tabularx}{\linewidth}{lX}
\toprule
\file{track.yaml} key & Meaning\\
\midrule
\texttt{name} & shown in the simulator and on the site\\
\texttt{direction} & \texttt{ccw} or \texttt{cw}\\
\texttt{checkpoints} & lap checkpoints; checkpoint 0 is the finish line\\
\texttt{max\_cars} & 1 for corridors too narrow to race side by side (Porto); default 4\\
\texttt{start} & optional \texttt{[x, y]} finish-line position; default: the straightest section\\
\texttt{walls.diameter} & air-duct diameter, 0.33~m like the league; omit for a cone-only track\\
\texttt{cones.spacing} & metres between cones on each edge, blue left, yellow right; omit for none\\
\bottomrule
\end{tabularx}

\subsection{Secret tracks}

Design competition tracks in \file{\textasciitilde/feb-secret-tracks/<name>/} with the same two
commands. The event file points at that folder and the harness passes it to the headless
simulator directly. After the event, move the folder into \file{tracks/}, commit, and cut an
app release so it ships inside the simulator as a practice track.

\section{Events}

One YAML per event in \file{events/}. Pushing it lists the event on the site.

\begin{lstlisting}
id: 2026-10-qualification
title: Fall 2026 Qualification
date: 2026-10-15
mode: time-attack            # or head-to-head
status: upcoming             # upcoming | live | done
track: ~/feb-secret-tracks/qual-2026-10
attempts: 2                  # best attempt counts
rules: {laps: 10, warmup_laps: 1, collision_penalty_s: 10, max_collisions: 10, timeout_s: 300}
entries: all                 # or a list of team names
\end{lstlisting}

\section{Race day: time-attack}

\begin{lstlisting}
cd ~/FEB/feb-racing
git pull                                    # latest submissions.yaml
./feb-race event 2026-10-qualification      # every registered image, N attempts each
git add results && git commit -m "qualification results" && git push
\end{lstlisting}

Each attempt: pull the image, start the container, start the headless simulator on the
secret track behind the 10~Hz proxy, probe laps and collisions inside the container, record a
bag, tear down, write \file{result.json}. Standings print at the end and the site rebuilds
itself on push. Afterwards set \texttt{status: done} in the event file and release the track.

One attempt takes about 3 minutes. Ten teams with two attempts is about an hour.
\cmd{--gui} on any harness command shows the simulator window instead of running headless.

\section{Finals: head-to-head}

\begin{lstlisting}
./feb-race bracket 2026-12-final --seed-from 2026-10-qualification
./feb-race h2h --teams "Team A" "Team B" --track tracks/loop --laps 10 --gui   # one race
\end{lstlisting}

Seeds come from the time-attack standings: single elimination, 1~v~N, 2~v~N$-$1, top seed
has a bye on an odd count. Each car runs in its own container behind the proxy, so every
container sees its own car as \texttt{roboracer\_1}, unchanged from time-attack. Results carry
the race id and position; the site shows the bracket. Two cars is the supported race mode;
three or more works end to end but drivers do not see each other, so treat it as experimental.

\section{Between events}

\begin{lstlisting}
./feb-race nightly                                  # rerun every registered image on every practice track
./feb-race verify results/practice/loop/<file>.json # rerun one self-reported entry
./feb-race standings 2026-10-qualification
./feb-race site                                     # rebuild site/data.json locally
\end{lstlisting}

Put \cmd{nightly} in cron on the PC and push \file{results/} afterwards. Self-reported practice
results arrive as pull requests that validate and merge themselves; the nightly turns them
verified.

\section{Releasing the simulator}

Needed only when the app itself changes or a released track should ship inside it.

\begin{lstlisting}
cd ~/FEB/feb-sim
./compile_check.sh                       # compiles Assets/FEB, no licence needed
./build.sh scene && ./build.sh linux && ./build.sh mac && ./build.sh windows
tar -C Builds/linux -czf FEB-Simulator-linux.tar.gz .
(cd Builds/mac && zip -qr ../../FEB-Simulator-mac.zip "FEB Simulator.app")
(cd Builds/windows && zip -qr ../../FEB-Simulator-windows.zip .)
gh release upload v0.1.0 -R Pranman1/feb-racing --clobber FEB-Simulator-*.tar.gz FEB-Simulator-*.zip
\end{lstlisting}

\cmd{feb-sim setup} downloads from the latest release. Build details and what the fork adds
are in \file{docs/build.md}. The RoboRacer vehicle prefab and the upstream scripts stay
untouched; everything FEB-specific is under \file{Assets/FEB}.

\section{Organiser checklist for the first run-through}

\begin{enumerate}
  \item Make the devkit package public on GitHub (Packages, \texttt{feb-devkit}, Package settings, Change visibility). Until then \cmd{feb-sim setup} fails at the pull for anyone but you.
  \item On a member laptop (your Mac): follow Part~II exactly as written, from \cmd{git clone} to \cmd{./feb-sim submit}. Note every step that needs a hint the manual does not give.
  \item Design the first secret track, write its event file, push it.
  \item Run \cmd{./feb-race event} once with the example team to see a full result land on the site.
\end{enumerate}
